# 에러 코드

마지막 수정: 2026-08-22

PromButter 백엔드가 내려주는 에러 코드 목록이다.
프론트엔드는 이 문서를 기준으로 화면 처리를 하면 된다.

> **새 에러 코드를 추가하면 이 문서에도 같이 적어 주세요.**
> 코드에만 있고 여기 없으면 프론트에서는 알 방법이 없습니다.
> 에러 코드 정의는 기획이 아니라 개발팀이 맡기로 했습니다 (2026-08-22, 효진님 확인).

## 응답 형식

에러가 나면 HTTP 상태 코드와 함께 아래 형태의 body 가 온다.

```json
{
  "error_code": "ERR-PROMPT-002",
  "message": "같은 제목의 프롬프트가 이미 있어요.",
  "detail": []
}
```

- `error_code` — 분기 처리에 쓰는 값. **화면에 그대로 띄우지 말 것.**
- `message` — 사용자에게 보여줄 한국어 문구. 그대로 써도 된다.
- `detail` — 있을 때만 온다. 개발자용 원인 정보라 화면에 쓰지 않는다.

## 이름 규칙

`ERR-<영역>-<번호>` 형태로 쓴다 (PB-112 에서 통일).

## HTTP 상태 사용 기준

| 상태 | 언제 |
|---|---|
| 400 | 요청 자체가 잘못됨 (OAuth 파라미터 누락 등) |
| 401 | 로그인이 안 되어 있거나 인증 정보가 틀림 |
| 404 | 대상이 없거나 내 것이 아님 (남의 것도 404 로 감춘다) |
| 409 | 이미 있는 것과 충돌 (제목·이름 중복) |
| 422 | 값 검증 실패, 개수 상한·쿼터 초과 |
| 5xx | 서버 또는 외부 서비스 문제 |

## 인증

| 코드 | 상태 | 언제 | 사용자 문구 |
|---|---|---|---|
| `ERR-AUTH-001` | 401 | 로그인 안 된 상태로 보호된 API 호출 | 인증이 필요합니다. |
| `ERR-AUTH-002` | 401 | 이메일 또는 비밀번호가 틀림 | 잘못된 인증 정보입니다. |
| `ERR-AUTH-003` | 400 | 이미 가입된 이메일로 가입 시도 | 이미 가입된 이메일입니다. |
| `ERR-AUTH-004` | 400 | 비밀번호 재설정 토큰이 유효하지 않거나 만료됨 | 유효하지 않거나 만료된 리셋 토큰입니다. |
| `ERR-AUTH-007` | 404 | 해당 사용자가 없음 | 사용자를 찾을 수 없습니다. |

## 워크스페이스

| 코드 | 상태 | 언제 | 사용자 문구 |
|---|---|---|---|
| `ERR-WORKSPACE-001` | 404 | 내 워크스페이스가 없음 (가입 시 자동 생성되므로 정상 흐름에선 안 남) | 워크스페이스를 찾을 수 없어요. |
| `ERR-WORKSPACE-002` | 404 | 경로의 `workspace_id` 가 없거나 남의 것 | 워크스페이스를 찾을 수 없어요. |

`ERR-WORKSPACE-002` 는 "없는 id" 와 "남의 워크스페이스" 를 **일부러 같은 응답으로 묶는다.**
남의 워크스페이스가 존재한다는 사실을 알려주지 않기 위해서다. 문구를 구체적으로 바꾸지 말 것.

2026-08-22 정리: 같은 상황을 가리키던 중복 두 자리를 `ERR-WORKSPACE-001` 로 합치고,
이름 규칙에서 벗어나 있던 `ERR-WORKSPACE-NOT-FOUND` 를 `ERR-WORKSPACE-002` 로 바꿨다.

## 구글 로그인 (OAuth)

이 계열은 **문구가 영문**이고 대부분 사용자에게 그대로 보여줄 수 없다.
화면에는 "로그인에 실패했어요. 다시 시도해 주세요." 같은 자체 문구를 쓰고, 원문은 로그만 남기는 것을 권한다.

| 코드 | 상태 | 언제 |
|---|---|---|
| `ERR-OAUTH-001` | 400 | 공급자가 에러를 돌려줌 |
| `ERR-OAUTH-002` | 400 | authorization code 없음 |
| `ERR-OAUTH-003` | 400 | state 쿠키 없음 (로그인 다시 시작해야 함) |
| `ERR-OAUTH-004` | 400 | state 가 유효하지 않거나 만료됨 |
| `ERR-OAUTH-005` | 500 | 로그인 마무리 실패 |
| `ERR-OAUTH-006` | 400 | 지원하지 않는 공급자 (로그인 시작) |
| `ERR-OAUTH-007` | 503 | Supabase OAuth 설정 안 됨 (로그인 시작) |
| `ERR-OAUTH-008` | 400 | 허용되지 않은 redirect_uri (로그인 시작) |
| `ERR-OAUTH-009` | 503 | 공급자 호출 실패 |
| `ERR-OAUTH-010` | 400 | 지원하지 않는 공급자 (연결) |
| `ERR-OAUTH-011` | 503 | Supabase OAuth 설정 안 됨 (연결) |
| `ERR-OAUTH-012` | 400 | 허용되지 않은 redirect_uri (연결) |
| `ERR-OAUTH-013` | 503 | Supabase OAuth 설정 안 됨 (토큰 교환) |
| `ERR-OAUTH-014` | 500 | 토큰 교환 실패 |
| `ERR-OAUTH-015` | 공급자 상태 또는 502 | 콜백 처리 중 Supabase 오류 |
| `ERR-OAUTH-016` | 공급자 상태 또는 401 | 토큰 교환 중 Supabase 오류 |

## 정리하면 좋을 것 (미결)

문서로 옮기면서 눈에 띈 것들이다. 정리할지 여부는 팀에서 정하면 된다.

1. **번호가 군데군데 비어 있다** (`ERR-AUTH-005/006`, `ERR-BODY-001`, `ERR-VAR-001`, `ERR-QUOTA-001`).
   옛 정의서 번호를 그대로 가져온 흔적이다. 굳이 메울 필요는 없고, 새 코드는 뒤 번호로 이어가면 된다.
